# Phase 1 Character Prototype — 설계 Spec

## Context

Phase 0에서 Unity Client와 .NET 10 서버가 접속·Spawn·이동 동기화(내 캐릭터 예측과 보정, 다른 플레이어 보간)까지 동작한다. 지형은 y=0 평면 하나뿐이고, 카메라는 캐릭터 뒤를 따라가기만 한다.

사용자 원래 요청의 Phase 1 — Character Prototype은 다음을 구현하고, 목적을 "기본적인 조작감 확인"으로 둔다.

```text
Third Person Controller / Camera / Move / Jump / Aim / Fire
```

Move와 Jump는 Phase 0에서 끝났다. 이번에는 조작감에 필요한 나머지를 만든다.

- 어깨 너머 카메라와 조준(ADS) 전환
- 카메라 충돌: 벽 뒤로 카메라가 들어가지 않음
- 부딪힐 지형(박스)과, 서버·예측이 같이 계산하는 캐릭터–지형 충돌
- 조준점(Crosshair)과 Client 전용 발사 연출

**성공 기준:**

- 두 Client가 박스로 된 테스트 아레나에서 움직인다. 벽을 통과하지 못하고, 벽을 따라 미끄러지고, 낮은 박스 위로 점프해 올라간다. 서버와 예측이 어긋나서 생기는 떨림은 없다.
- 카메라는 오른쪽 어깨 너머에 있다.
  - 우클릭을 누르는 동안 가까이 당겨지고 시야각이 줄어든다.
  - 벽에 붙어도 벽 안쪽을 보여 주지 않는다.
- 좌클릭을 누르고 있으면 조준점 방향으로 초당 10발 궤적과 탄착 표시가 나온다. 로컬 연출이며 서버에는 가지 않는다.
- 충돌 규칙은 Unity 없이 `dotnet test`로 검증된다.

## 사용자가 고른 것

| 질문 | 선택 |
|---|---|
| Phase 1 범위 | 카메라 + 간단한 지형(플레이어도 벽을 통과하지 못함) |
| 충돌 방식 | Shared 박스 충돌(AABB) |
| 나머지 결정 | "추천안으로 계속, 추천 이유는 문서로 남긴다" |

## 1. Shared: 지형과 충돌

```text
Shared/Runtime/Simulation/
  Box.cs              readonly struct Box { Vector3 Min, Max; Center/Size 생성 도우미 }
  TestArena.cs        static ReadOnlySpan<Box> Boxes  (코드 상수, 테스트 아레나)
  MoveSettings.cs     + HalfWidth 0.35, Height 1.8, Skin 0.001, GroundProbe 0.02
  MovementSimulation.cs
      Step(ref MoveState, in InputCommand, float dt, ReadOnlySpan<Box> world)
```

**`Step` 순서:**

1. 입력을 검증한다. 비유한 값은 0으로, 이동 길이는 1 이하로 만든다. Yaw 처리와 수평 속도 계산은 Phase 0과 같다.
2. 캐릭터 AABB가 박스와 `Skin`보다 깊게 겹치면, 그 박스에 대해 가장 적게 겹친 축으로 밀어낸다(D4).
3. 접지를 판정한다(D3). 접지면 Y를 면에 맞추고 `VelocityY = Jump ? JumpSpeed : 0`, 공중이면 중력을 더한다.
4. X Sweep → Z Sweep → Y Sweep 순서로 이동한다(D2).
   - 각 축에서, 나머지 두 축 범위가 겹치는 박스 가운데 진행 방향으로 가장 가까운 면까지만 이동하고 `Skin`만큼 띄운다.
   - Y가 아래로 막히면(바닥 y=0 포함) `VelocityY = 0`. 위로 막히면(천장) `VelocityY = 0`.
5. 할당·예외·잠금이 없다. 박스 수를 N이라 하면 O(N) × 상수다.

`world`가 비어 있으면 결과는 Phase 0과 같다. 바닥 y=0만 있고 동작이 동일하므로 기존 이동 테스트는 모두 통과해야 한다.

**`TestArena`:**

- 약 40 × 40 m 외곽 벽. 높이 3 m, 두께 1 m.
- 벽 조각 여러 개. 높이 3 m, 카메라 충돌 확인용.
- 기둥. 1 × 1 × 3 m.
- 낮은 박스. 높이 1 m, 점프로 오를 수 있음.
- 높은 박스. 높이 1.5 m, 점프로 오를 수 없음.
- 플랫폼. 높이 1 m 박스 위에 다시 1 m 단.
- **중앙 반경 7 m는 비워 둔다.** 서버 Spawn 위치가 반경 5 m 원 위이기 때문이다(`Match.SpawnPosition`).
- 박스 수는 30개 이하.
- **박스끼리 옆으로 맞닿거나 겹치지 않는다**(위로 쌓는 것은 허용). 박스를 하나씩 밀어내는 보정(D4)이 면을 공유하는 박스 사이에서 캐릭터를 가둘 수 있기 때문이다. 외곽 벽의 네 모서리는 0.5 m 틈으로 둔다. 캐릭터(0.7 m)보다 좁아 아레나는 막힌 채로 유지된다.

## 2. Server

- `Match.Tick`이 `MovementSimulation.Step(..., TestArena.Boxes)`를 호출한다. 그 밖의 서버 구조(스레드, Channel, Snapshot)는 바뀌지 않는다.
- `ProtocolConstants.ProtocolVersion = 2`(D6).
- Snapshot 형식은 그대로다(D3).

**카메라 흐름:**

1. `LateUpdate`에서 머리 기준점(발 + 1.6 m)을 잡는다.
2. 어깨점(오른쪽 오프셋)과 목표 카메라 위치(뒤로 거리)를 계산한다.
3. SphereCast 두 번으로 막힌 거리를 구한다.
4. 막혔으면 즉시 당기고, 풀리면 감쇠하며 돌아간다.
5. 캐릭터 Yaw는 지금처럼 카메라 Yaw를 입력으로 보낸다.

**Lifetime:**

- Crosshair Canvas, 궤적과 탄착 풀, 지형 Material은 GameClient가 만들고 OnDestroy에서 제거한다.
- 풀은 고정 크기라 늘어나지 않는다.

**Hot Path(Update, 발사):**

- 할당하지 않는다.

## 5. 테스트

**Shared 충돌** (xUnit, `Server/tests`):

- 빈 지형이면 Phase 0 테스트가 그대로 통과한다.
- 벽을 향해 걸으면 벽 면에서 멈추고 겹치지 않는다.
- 벽에 대각선으로 부딪히면 벽과 평행한 방향으로 계속 움직인다.
- 1 m 박스로 점프하면 윗면에 서고, 접지 상태이며 `VelocityY = 0`이다.
- 1.5 m 박스에는 점프로 오를 수 없다.
- 박스 위에 서 있으면 여러 Step 동안 Y가 변하지 않는다(떨림 없음).
- 천장에 머리가 닿으면 `VelocityY = 0`이다.
- 빠른 낙하(여러 m/Tick)로도 0.2 m 두께 판을 뚫지 않는다.
- 박스 안에서 시작하면 밖으로 밀려난다.
- 같은 입력이면 같은 결과가 나온다(결정성).
- NaN 입력에서도 박스와 겹치지 않고 위치가 유한하다.

**`TestArena`:**

- 모든 박스가 `Min < Max`다.
- Spawn 위치(EntityId 1–50)의 캐릭터 AABB가 어떤 박스와도 겹치지 않는다.
- 박스 수가 30 이하다.
- 어떤 두 박스도 옆으로 맞닿거나 겹치지 않는다(`NoTwoBoxesTouchSideBySide`).

**Server:**

- 기존 통합 테스트가 모두 통과한다.
- ProtocolVersion 테스트를 2로 갱신한다.

**Client EditMode**(Unity 밖 NUnit 스크래치로 선검증):

- 박스 지형에서 예측이 서버와 같은 결과를 낸다.
- 어깨 카메라 순수 계산: 기본/ADS 목표 위치, 막힌 거리가 적용된 위치.
- 발사 누적기: 10발/초이고, 프레임이 튀어도 한 프레임에 쏘는 수에 상한이 있다.

**Unity:**

- Editor 자동 import 후 `Editor.log`에 컴파일 오류가 없는지 확인한다.
- 수동 확인은 사용자가 한다.
  - 벽에 붙어 카메라를 돌린다.
  - 박스에 점프로 오른다.
  - 우클릭으로 조준하고, 좌클릭으로 발사한다.
  - 두 Client로 벽 충돌이 떨림 없이 동기화되는지 본다.
