# Phase 13 Harvesting & Building — 설계 Spec

## Context

사용자 요청서 원문은 `Docs/requests/2026-10-02-phase13-harvesting-building-request.md`에 있고, 이 문서가 따르는 근거다. 목표:

- 자원 채집, 환경 파괴, 건설 모드, Wall·Floor·Ramp·Roof, 연속 건설(Turbo), 구조물 파괴, 지지·붕괴, 건설 동기화를 만든다.
- 다른 게임의 에셋·이름·UI·코드·그래픽은 쓰지 않는다.
- 핵심 기준은 "총격 중에도 즉시 건설해 방어하고 높이를 확보할 만큼 빠르게 반응한다"이다.
- 성능 전제: 플레이어 100명, 수천 개 구조물, 지금의 Snapshot 성능 유지, 구조물이 늘어도 Tick이 안정적일 것.

**지금 구조에서 확인한 사실(설계의 근거, `main` 7f9a559 기준):**

- **이동 충돌:**
  - `MovementSimulation.Step`은 상자 배열(`ReadOnlySpan<Box>`) 전체를 Tick마다 5–6번 선형으로 훑는다. 정적 상자 58개와 문 5개, 공간 색인은 없다.
  - 서버(`DoorSet`)와 예측(`PredictedDoors`)이 같은 배열을 만든다. 문은 배열 위치로 식별한다.
- **바닥:** 바닥 높이는 지형(`HeightField`)과 상자 윗면뿐이다. 경사면과 계단 오르기가 없고, 최대 경사는 0.6이다.
- **맞닿은 상자:** 옆면이 맞닿은 상자는 하나씩 처리하는 밀어내기(`Depenetrate`) 때문에 캐릭터를 가둔다. Phase 1 규칙과 `GameMapTests`가 금지한다.
- **사격:** `HitScan.TraceWorld`도 모든 상자를 선형으로 훑고, 거리만 돌려준다.
- **무기:** 카탈로그는 탄약·탄창이 필수다. 무기 칸은 정확히 3개다.
- **아이템:** 월드 아이템은 종류 3개, 최대 256개, E로 줍는다. 자동 줍기는 없다.
- **네트워크:**
  - 신뢰 패킷은 모두 채널 0의 ReliableOrdered 하나를 쓴다. 묶음 전송(Batching)은 없다.
  - Snapshot 헤더 27 B, 90명 패킷 1197 B로 3 B만 남는다.
  - Entity 플래그 bit6·bit7, 입력 비트 4096·8192·16384·32768이 빈다. 패킷 Id 최대값은 25, Protocol은 10이다.
- **초기화:** 판이 끝날 때(`CloseRound`) 문을 닫지 않고, 다음 `StartMatch`에서 닫는다. 개발 모드(`DevRespawn`)는 판이 없다.
- **현재 성능:** 50명 Tick p95 0.06–0.14 ms(Phase 12).

  - 올바른 타격, 범위 밖, 방향 틀림, 쿨다운
  - 피해, 자원, 최대치, 파괴, 파괴된 대상 다시 때리기
  - 약점 맞음, 약점 빗나감
- **배치:**
  - Wall·Floor·Ramp·Roof 정상 배치
  - 자원 없음, 범위 밖, 막힘, 이미 있음, 지지 없음
  - 회전·종류·재료 잘못, 관전자, 죽음, 잘못된 경기 상태
- **자원:**
  - 차감, 실패 시 차감 없음, 중복 요청 시 한 번만 차감, 최대치
  - 죽음 드롭, 자동 줍기
- **구조물 피해:**
  - 총, 채집 도구, 건설 중 체력
  - 파괴, 이미 파괴됨, 같은 Tick 여러 피해
- **지지:**
  - 땅 위 벽, 벽 + 바닥, 벽 + Ramp, 여러 연결
  - 기초 파괴, 부분 지지, 붕괴, 큰 덩어리
- **네트워크:**
  - Placed·Destroyed 복제, 중복·순서 바뀐 사건, 묶음
  - 관심 진입·이탈, 재접속 동기화, 큰 Sync 나누기
- **보안:**
  - 요청 폭주, 재전송, 불가능한 좌표(int 경계·맵 밖)
  - 잘못된 Id, 자원 조작, 거리 조작, 속도 조작, 벽 너머 배치

- **이동:**
