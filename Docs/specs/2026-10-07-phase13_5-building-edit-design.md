# Phase 13.5 Building Edit — 설계 Spec

## Context

요청서는 `Docs/requests/2026-10-05-roadmap-phase13_5-19-request.md`의 STEP 3(§12–§31)이다. 목표는 Phase 13 건설을 실제 전투에서 빠르게 편집할 수 있게 하는 것이다: Build → Edit → Open → Shoot → Reset / Rebuild.

**지금 구조에서 확인한 사실(설계의 근거, `main` e6596c5 기준):**

- **모양:** 조각 모양은 `BuildPieceShape`(종류, x, y, z, 회전)뿐이다. 벽·바닥은 상자 하나(`BuildGrid.BoxOf`), 경사로·지붕은 `Slope` 하나(`SlopeOf`)다. 이 함수를 쓰는 곳은 `CollisionWorld.Gather`, `PieceTrace`, `BuildRules`, `Match`(Vault 경로), Client `PieceMeshes`·`BuildPieceViews`·`BuildController`, QA `BuildLayouts`뿐이다.
- **와이어:** Placed 기록의 격자 u32는 20비트만 쓴다(x5 z5 y4 회전2 종류2 재료2). 위 12비트가 비어 있다. 리더는 비트 20 이상이 켜지면 거부한다.
- **저장:** 서버 `BuildWorld`는 슬롯 키 → id, `PieceGrid`는 id → 칸이다. 경사로의 회전은 슬롯 키에 들어가지 않는다. 그래서 회전을 바꿔도 슬롯은 그대로다.
- **지지:** `BuildSupport.Edges`는 모양만으로 정해진다. 경사로 회전이 바뀌면 모서리가 바뀐다. 파괴 뒤 탐색은 Tick 끝에 한 번 돈다(`_starts`).
- **요청:** `BuildRequest`(9 B)는 연결마다 u16 순번을 쓴다. 플레이어마다 큐 8개가 있다. 0.1초마다 하나를 받아들이고 초당 20개를 넘으면 잘못된 패킷으로 센다.
- **Client:** `BuildStore`는 같은 id의 모양이 바뀐 Placed를 이미 제자리 갱신한다(Grid 제거 후 다시 추가). 조각 Mesh는 공유 3개(상자, 경사로, 지붕)다. 겨누는 조각을 찾는 함수는 없다(`FindAimPoint`는 점만 돌려준다). G는 무기 버리기라 비어 있지 않다. 비어 있는 키는 H, Y, U, I, O, P, J, K, L, M, N, Tab, 6–0 등이다.
- **소유자:** `BuildPieceRecord.Owner`(건설자 Entity id)는 Phase 13에서 "Phase 13.5 편집 권한"으로 미리 실어 두었다.
