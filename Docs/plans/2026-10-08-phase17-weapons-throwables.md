# Phase 17 Weapons / Throwables — 구현 기록 (Spec과 다른 점)

설계: `Docs/specs/2026-10-08-phase17-weapons-throwables-design.md`(D1–D18). 동작 설명: `Docs/Weapons.md`, 패킷: `Docs/Networking.md`. 이 문서에는 구현하면서 Spec에 없던 것을 정했거나 Spec과 다르게 한 것만 적는다.

## 서버

| # | 내용 | 이유 |
|---|---|---|
| S1 | 감쇠: AR 50 m→0.7, SMG 25 m→0.6, SG 8 m→0.3, Pistol 20 m→0.6, 저격 없음. 권총 사거리 80 m·재장전 1.4 s, SG 재장전 2.4 s, 로켓 발사 간격 1 s. 반동 AR 0.6°·LR 3°·SMG 0.4°·SG 4°·P 1.5°·RL 5°. 로켓의 `damage` 75는 와이어 검사(1 이상)를 위한 표시값이고 실제 피해는 투사체 정의의 폭발 피해다. | Spec이 수치를 정하지 않았다. 역할이 분명하게(근거리 SG, 중거리 AR, 근접 SMG) 나뉘게 했다. |
| S2 | 수류탄: 중력 9.81, 조준보다 8° 위로 던짐, 던지기 간격은 `weapons.json` `projectiles.Grenade.throwIntervalSeconds`. 수류탄 폭발은 Common(1.0), 로켓은 무기 등급. | `items.json`에 두면 소모품 `useSeconds`의 의미와 섞인다. |
| S3 | 투사체 정보 목록(수류탄 포함)을 `WeaponCatalog` 패킷 끝에 붙인다. | Client가 수류탄의 중력·반지름도 알아야 한다. |
| S4 | 폭발 거리는 몸 상자·조각 경계 상자까지 잰다(시선은 몸 중심까지). 처리 순서는 플레이어 → 조각(그 폭발이 부순 벽도 시선에서는 서 있음). 폭발 위치는 맞은 면에서 법선으로 0.05 m 밖. | 벽 면 2 m 앞의 폭발이 중심 기준이면 더 멀게 계산된다. 시선이 표면 안에서 시작하지 않게 한다. |
| S5 | Starting(시작 카운트다운)에서도 투사체를 만들지 않는다(Waiting·Playing·FinalPhase만). 대기실에서 던진 수류탄은 Starting에서 피해 없이 폭발 패킷이 갈 수 있고, Client는 모르는 id를 무시한다. | Client가 Starting 진입 때 투사체를 비우므로 서버와 맞춘다. |
| S6 | 수류탄은 위를 향한 면(법선 Y ≥ 0.7: 바닥·지형·Ramp·지붕 경사)에서 느려질 때만 멈춘다. 벽·천장에서는 계속 튕기며 떨어진다. 정지한 수류탄은 밑의 조각이 부서져도 떨어지지 않는다(퓨즈 3 s, 단순화). | 리뷰: 벽·천장에 느리게 닿으면 공중에 붙어 그 높이에서 터졌다. |
| S7 | 재접속 재전송의 `ProjectileSpawned.OwnerId`는 주인이 지금 없으면 0이다. | 리뷰: 나간 주인의 Entity id가 다시 쓰여 다른 사람으로 보일 수 있었다. |
| S8 | 수류탄 던지기는 도구·재장전과 무관하다(재장전 중에도 가능). 6 누름은 소생·재투입 진행도 끊는다. | 회복 취소 규칙과 같은 흐름이다. |
| S9 | 산탄 대상이 같은 사격의 앞선 명중으로 이미 탈락했으면 건너뛴다(팀 전멸로 기절 팀원이 함께 탈락하는 경우). 피해 0(감쇠 비율 0)도 건너뛴다. | 탈락자에게 `HitConfirmed`·피해 기여가 가지 않게 한다. |
| S10 | 봇은 로켓·로켓 탄·수류탄을 줍지도 쓰지도 않는다. | Spec D15. 부하 시험에서 폭발이 섞이지 않게 한다. |
| S11 | Loot 표의 `weapons`·`ammo` 목록은 id로 적고, 없으면 카탈로그 전체다(테스트 데이터 호환). Phase 16 `FloorLootRegressionTests` 해시는 무기 6종·탄 5종 때문에 의도적으로 새로 잡았다(테스트에 이유). | Spec D13. |
| S12 | QA: 입력 녹화의 알려진 버튼 마스크에 `InteractHeld`·`ThrowGrenade`를 넣었다(이제 u16 전 비트가 알려짐). | 녹화 재생 때 unknown으로 세던 것을 고친다. |

## Client

| # | 내용 | 이유 |
|---|---|---|
| C1 | 내 예광탄은 Client 자체 퍼짐(표시용), 원격 사격은 `ShotFired` 끝점. | Client는 서버 Tick·발 번호를 몰라 서버 시드를 재현할 수 없다(Spec D3). |
| C2 | Starting·Finished·Closing에서는 투사체 무기의 발사·탄 감소·재장전·반동을 예측하지 않는다(`WeaponState.LaunchAllowed`, 재실행에도 유지). 서버 투사체 칸 32개가 찬 경우는 Snapshot 교정에 맡긴다. | 리뷰: 카운트다운·결과 화면에서 로켓을 쏘면 HUD와 카메라가 깜빡였다. |
| C3 | 투사체 표시는 끊김, Join/Resume, MatchState가 Waiting/Starting/Finished로 **바뀔 때만** 비운다. 입장 뒤 첫 MatchState는 바뀜으로 보지 않는다. | Phase 16: 늦게 온 MatchState가 막 받은 상태를 지운 일이 있었다. |
| C4 | 수류탄 키 6은 행동 불가 모드(기절 포함)이거나 수류탄이 0이면 입력에서 뺀다. | 불필요한 입력을 줄인다(서버도 막는다). |

## 측정

`stress-quick` 5/5 PASS(50명). Mixed Match Tick p95 0.311 ms, 이전 기준선 대비 50 % 넘게 나빠진 지표 없음. 투사체·산탄 Tick 경로는 할당이 없다(테스트 고정).

## 함께 고친 것

- `WorldItemsTests.AddSearchRemove_AllocateNothing`: 측정 전에 같은 호출을 한 번 예열한다. 첫 호출의 JIT·정적 초기화 할당이 전체 실행에서 가끔 섞여 실패했다(6회 중 2회 → 예열 뒤 6회 연속 통과).

## Known Issues

- 서버 투사체 칸(32개)이 모두 찬 상태에서 로켓을 쏘면 Client는 쏜 것으로 예측했다가 Snapshot으로 바로잡는다.
- 아주 짧은 클릭(시뮬레이션 Step 하나보다 짧은 누름)은 반자동 사격에서 입력이 빠질 수 있다(Unity QA의 기본 클릭에서 발견, 150 ms 누름은 정상).
- 3인칭 카메라의 기본 조준선은 약 24 m 앞 바닥을 가리켜, 그대로 쏜 로켓은 바닥에서 터진다(조준 문제, 게임 규칙대로).
- 정지한 수류탄은 밑의 조각이 부서져도 떨어지지 않는다(S6).
