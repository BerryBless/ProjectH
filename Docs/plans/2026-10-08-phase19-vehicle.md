# Phase 19 Vehicle — 구현 기록 (Spec과 다른 점)

설계: `Docs/specs/2026-10-08-phase19-vehicle-design.md`(D1–D16). 동작 설명: `Docs/Vehicles.md`, 패킷: `Docs/Networking.md`. 이 문서에는 구현하면서 Spec에 없던 것을 정했거나 Spec과 다르게 한 것만 적는다.

## 서버

| # | 내용 | 이유 |
|---|---|---|
| S1 | 잔해(Wrecked)는 사격·로켓·폭발을 막지 않고 피해도 받지 않는다(5 s 뒤 사라짐). 건설 설치 거절은 잔해도 본다. | 곧 사라지는 물체가 전투를 막지 않게 한다. |
| S2 | 광선 시작점을 품은 차량 상자는 건너뛴다. 차량은 차체와 겹쳐 서 있는 플레이어(되감은 몸)를 가리지 않고, 그 플레이어보다 가까울 때만 가린다. | 리뷰: 차체 안에 선 플레이어가 밖으로는 쏘고 안으로는 맞지 않는 한쪽 엄폐가 됐다. |
| S3 | 강제 내리기 대체 자리 = 차량 높이 + 2 m. 착지 속도 약 8.9 m/s로 낙하 피해 기준(13 m/s) 아래다. 내릴 자리 순서: 왼쪽(운전석) 2 m → 오른쪽 → 뒤 3.2 m → 앞 3.2 m. | Spec D6의 "차체 위"를 수치로 정했다. |
| S4 | 차량 피해는 누구든(같은 팀 포함) 줄 수 있고, 파괴 크레딧만 탑승자 기준 적에게 준다. 치기 쿨다운은 플레이어 하나에 대해 모든 차량 공통 1 s. | 크레딧 규칙(D7)만 팀을 보면 충분하다. |
| S5 | 타는 순간 같은 입력의 다른 행동(사격·휘두르기·수류탄·회복 시작)을 하지 않고, 탄 동안 회복은 끝나지 않는다. 진입 때 회복·소생 채널을 끊고 재장전은 이어진다. | 리뷰: E와 함께 누른 사격·회복이 좌석에서 실행됐다. |
| S6 | 편집으로 다시 채워지는 칸이 쓰는 중인 차량 발자국에 닿으면 편집을 거절한다(`Blocked`). | 리뷰: 벽 구멍에 걸친 차량을 편집으로 가두면 시작 겹침 무시 때문에 차량이 벽을 통과했다. |
| S7 | 마지막 차량이 사라지면 Count 0 패킷을 한 번 보낸다. 연결이 끊겨 내려진 운전자는 유예 중 입력 반복(마지막 이동)을 하지 않는다. | 리뷰: 경기 끝에 Client가 1 s 동안 탄 상태로 남았고, W를 누른 채 끊긴 운전자가 0.5 s 걸어갔다. |
| S8 | QA `spawnVehicle`은 차량 Step과 같은 후보(맵 상자·문·채집 대상·조각·경사면)와 겹치면 409. QA `spawnBuildPiece`는 기존처럼 차량을 검사하지 않는다. | 시나리오가 잘못된 이유로 통과하지 않게 한다. 조각 설치 명령은 준비용이다. |
| S9 | 생성 위치 하나를 (14, −30)에서 (−14, −30)으로 옮겼다. | 기존 Unity 건설 스크린샷 시나리오의 카메라 앞이었다. |
| S10 | 서버 Health 줄에는 차량 수치를 넣지 않았다. `/qa/vehicles`가 누계(spawned·wrecked·enters·exits·impacts·runOvers·statesSent)를 보여 준다. | Health 줄 형식을 바꾸지 않는다. |
| S11 | 봇은 아이템 옆에서 E를 눌러 차에 타면 바로 내린다. | Spec D16 "봇 운전 없음". |

## Client

| # | 내용 | 이유 |
|---|---|---|
| C1 | 충돌 소리는 서버 사건이 없어 기록 사이 속도 감소로 판정한다(이전 속도 ≥ 5 m/s, 감소 > 24·Δt + 2 m/s, Δt ≤ 0.25 s). 내 차량도 기록 기준이다. | 사건 하나 = 소리 하나. 예측 결과로 내면 Reconcile 때 두 번 날 수 있다. |
| C2 | 내리기 입력 뒤의 입력에는 제동(Jump)을 싣지 않는다. 서버가 내리기를 거절한 것이 확인되면(나를 아직 적은 기록의 ack ≥ 내리기 입력) 다시 싣는다. | 리뷰: Space를 누른 채 내리면 서버가 내린 뒤의 입력을 걷기로 처리해 약 왕복 지연만큼 점프했다. 서버가 아니라 Client에서 빼야 서버와 예측의 재실행이 같다. |
| C3 | 관전 중 탄 사람을 볼 때는 표준 카메라다(차량 카메라는 내 몸만). | 범위를 지킨다. |
| C4 | `/qa/status`에 `vehicle` 객체(audio 뒤)를 더했다. 탄 상태가 아니면 vehicleId 0, seat −1. | Unity 시나리오가 탄 상태·속도·체력을 읽는다. |
| C5 | 새 소리 종류는 `Count` 바로 앞에 더해 기존 소리의 번호와 합성 시드가 바뀌지 않게 했다. | Phase 18 클립이 그대로다. |

## 측정

- `stress-quick` 5/5 PASS(직전 Phase 18 실행과 비교해 50 % 넘게 나빠진 지표 없음).
- `stress-gameplay` 10/10 PASS. Combat 하나가 경고를 냈다: `server.tickP99Ms` 0.068 → 0.104 ms(+54 %, 기준선은 2026-10-02 실행). 같은 시나리오를 두 번 다시 돌리니 0.044·0.042 ms로 기준선보다 낮았다. 경고 실행의 값은 4 ms 표본 하나 때문이다(잡음). 나머지 9개는 50 % 넘게 나빠진 지표가 없다.
- 차량 Tick 경로는 할당이 없다(`DrivingTicks_WithVehicleStates_AllocateNothing`).

## 간헐 실패 (Phase 19 코드와 무관)

- 할당 측정 테스트 `SnapshotSplitTests.SendingASplitSnapshot_AllocatesNothing`, `BotBrainTests.ALootOrWanderTick_AllocatesNothing`가 전체 실행에서 가끔 한 번 실패하고 다시 돌리면 통과한다(따로 10번 모두 통과). Phase 17의 `WorldItemsTests`와 같은 첫 호출 JIT 할당 종류로 보인다. 봇 변경은 필드 읽기와 입력 비트뿐이다.
- Unity `audio_footstep`의 순간이동 검사가 약 7번에 1번 발소리 하나를 더 센다(Phase 18 시나리오, 발소리 코드는 탄 사람 무음만 더함).

## Known Issues

`Docs/Vehicles.md` "Known Issues"에 모았다: Client 차량 Collider 없음(조준·Ping·로컬 예광탄이 지나감), 차량 맞힘 표시 없음, 수류탄·차량끼리·플레이어가 차체를 통과, 엔진 연속음 없음, 회전하지 않는 발자국, 조수석 카메라 약 130 ms 지연, 봇·Stress Brain은 차량을 모름.
